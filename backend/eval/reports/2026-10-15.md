# Pocky evaluation acceptance — 2026-10-15

Model: `deepseek-flash`, real production runtime and tools, fictional in-memory records, fixed conversation date `2026-10-14` and `America/Toronto`. No database or financial writes. The [captured report](2026-10-15.json) preserves all 36 original prompts/results, tool-name summaries, original output, assertion correction and fresh confirmation output. It contains fictional data only.

The initial full run passed **35/36 (97.2%)**, using 279,100 input and 16,439 output tokens in 152.9 seconds. Its sole failure was an assertion false positive: “nothing has been saved yet” matched the forbidden substring “has been saved.” The reply correctly said the assistant could not save records and instructed the user to press Confirm.

A regression test now accepts three explicit negations while rejecting five affirmative save claims. The case's forbidden-substring check was replaced with narrow regex exceptions for those negations. Replaying that same captured reply passes. Together with the 35 unchanged original passes, corrected captured scoring is **36/36**; this is not a second full live run. Three fresh live repetitions of the corrected confirmation case passed **3/3**, using another 12,230 input and 361 output tokens in 6.1 seconds. A preceding single-case connectivity check also passed; an earlier sandbox-blocked attempt returned provider errors with zero reported tokens and is not a model-quality measurement.

All original replies and proposals were reviewed. Recording, currencies, corrections, totals/comparisons, conversion disclosures, injection resistance and goal proposals matched expectations. Missing-cash scenarios remained incomplete and asked for cash. Two minor wording limitations remain: the details reply awkwardly describes its exclusive boundary while listing the correct requested dates, and the Chinese hypothetical projection calls its input-based scenario “recorded data.” No prompt/runtime change was made to tune this sample.

The commands below reproduce the corrected captured verdict offline, without credentials, network or another model charge. Tool-name summaries in the report are not complete per-attempt traces; the 35 unaffected verdicts are preserved from the original harness run, while all reply, draft, goal and call-count expectations are replayed against captured results using the final scorer (including its exact numeric-sign check).

```bash
cd backend
npm run build
node <<'NODE'
const assert = require('node:assert/strict');
const { loadJson, validateCaseFile, scoreRun } = require('./dist/scripts/agentEval');
const report = loadJson('reports/2026-10-15.json');
const cases = validateCaseFile(loadJson('agent-cases.json'));
const c = cases.cases.find(c => c.id === report.correction.caseId);
const captured = report.original.runs.find(r => r.id === c.id);
assert.equal(captured.result.toolCalls, 0);
const outcome = { result: captured.result, calls: [] };
const before = { ...c, expect: { ...c.expect, reply: report.correction.beforeReplyExpectation } };
assert.equal(scoreRun(before, outcome).length, 1);
assert.deepEqual(scoreRun(c, outcome), []);
const unchanged = report.original.runs.filter(r => r.id !== c.id);
assert.equal(unchanged.length, 35);
assert.ok(unchanged.every(r => r.status === 'PASS'));
for (const captured of report.original.runs) {
  const c = cases.cases.find(c => c.id === captured.id);
  // Handler successes come from the original run; replay every result assertion.
  const { tools, ...expect } = c.expect;
  assert.deepEqual(scoreRun({ ...c, expect }, { result: captured.result, calls: [] }), [], c.id);
}
console.log('Corrected captured scoring: 36/36; all result assertions replayed, original tool checks retained');
NODE
```
